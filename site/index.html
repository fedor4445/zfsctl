zfsctl

A terminal UI and daemon for managing ZFS. One screen for pools, datasets, snapshots, disks, shares and boot environments; a daemon that runs your snapshot, replication, backup and scrub jobs and tells you when something needs attention. It manages other machines over ssh, with no agent to install on them.

what it does

  • Pools, vdevs, datasets, properties, quotas, snapshots, disks and SMART, NFS and SMB shares, boot environments.
  • Scheduled jobs: snapshots with retention, host-to-host and stream-file replication (raw sends for encrypted datasets), restic backups, rclone cloud mirrors.
  • Native encryption: create encrypted datasets, load, unload and change keys. Passphrases never appear in an argument, a log or a file.
  • Alerts and a daily report by mail or hook, and a Dashboard that shows what needs attention first.
  • A protection check: every dataset needs snapshots and a copy on another machine, or it is flagged on the Dashboard and by mail, with the form that fixes it one keystroke away.
  • Every change asks twice (y, then Enter); what cannot be undone makes you type the name.
  • Hosts run FreeBSD, Linux or illumos. Root only through a sudoers file you read first (zfsctl print-sudoers).

install

From source, on the FreeBSD hub that will run it (a Rust toolchain is the only requirement):

# build
cargo build --release
# install and start the daemon
install -m 755 target/release/zfsctl /usr/local/bin/zfsctl
install -m 555 contrib/rc.d/zfsctl /usr/local/etc/rc.d/zfsctl
sysrc zfsctl_enable=YES && service zfsctl start
# the screen
sudo zfsctl

The book covers configuration, the sudoers rules for remote hosts, and every screen: installing, remote hosts, recipes.

status

in development. The first public release is not out yet; the name zfsctl is reserved on crates.io.

built on

zfsctl drives other people's work and bundles none of it: OpenZFS, FreeBSD, illumos (tested on OmniOS), Linux, Rust, ratatui, restic and rclone. With thanks to all their authors.
