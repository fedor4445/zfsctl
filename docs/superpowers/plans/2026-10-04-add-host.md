# Add Host Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user add a new remote host to `zfsctl` from inside the Hosts section of the TUI — validated for SSH reachability, usable immediately in the same session (no restart), and persisted to `config.toml` so it survives one.

**Architecture:** A new `'n'` key in the Hosts section opens a form (`Name`, `SSH target`). Local validation (blank/duplicate name) keeps the form open immediately, same as every other form. Once valid, the form closes and a background thread probes reachability with the already-existing `SshRunner` (`ssh -o BatchMode=yes -o ConnectTimeout=10 -- <target> true`, checked via the already-existing `zfs::run_checked` so a non-zero exit — unreachable host, bad auth — is correctly treated as failure, not success). On success, `App` records a `pending_new_host` signal; the main event loop (which owns the live `HostInventory`, something `App` never has direct access to) applies it: pushes the host onto the live inventory (hot-reload) and persists it to `config.toml` via a new, fully unit-tested `hosts::apply_new_host` function that never rolls back the inventory push even if persisting fails.

**Tech Stack:** Rust (2021 edition), ratatui 0.29, crossterm 0.28, `tempfile` (dev-dependency, already in use by `config.rs`'s own tests) — no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-04-add-host-design.md`.

## Global Constraints

- This crate has **no `[lib]` target** — every test command in this plan is plain `cargo test ...`, never `cargo test --lib ...`.
- **Add-only in this pass.** Removing or editing a host from the TUI is explicitly out of scope (see spec's Non-goals).
- **SSH key bootstrap stays manual, out of scope.** This feature assumes passwordless SSH to the new host already works; it never prompts for a password or pushes a key.
- **The form closes on submit, before the async probe resolves** — consistent with every other mutation-triggering form in this app (scrub, destroy, etc. all close their modal immediately and report the outcome later via `status_message`). A failed probe is retried by pressing `'n'` again, not by reopening the same form instance.
- **Duplicate-name check is case-insensitive** and must include `"local"` specifically (it's always the first entry in `self.hosts`, not something read from `config.toml`).
- **A `Config::save` failure must never roll back the already-applied `inventory.hosts` push** — the host stays usable for the rest of the session either way; only a warning is shown.
- Register any new module-level item (enum variant, struct field) in the same step that first references it, not deferred to a later step — an unregistered item is invisible to the compiler, so an intermediate test run against it wouldn't produce a real RED, just a different error, defeating the point of watching it fail.

## Review Focus

- A Name or SSH target field containing only whitespace (e.g. `"   "`) must be treated as blank after trimming, not accepted as a distinct valid value.
- A name that differs from an existing host only by case (e.g. `"Local"` vs `"local"`, or `"FB16"` vs an existing `"fb16"`) must be rejected as a duplicate, not silently accepted as a second, confusingly-similar entry.
- The SSH probe can take up to 10 seconds (the existing `ConnectTimeout=10`) on an unreachable host — this must never block the main event loop; it must run on its own thread, exactly like every other async refresh/mutation in this app.
- A `Config::save` failure after a successful probe (e.g. the config directory becomes unwritable) must leave the host usable for the rest of the session — the inventory push must never be rolled back — while still surfacing a clear warning that it won't survive a restart.
- Submitting the form with only one of the two fields filled in (Name filled, SSH target blank, or vice versa) must keep the form open with nothing accepted — neither field has a sensible default to silently fall back to.

```rust
    /// Spawns the SSH reachability probe for a candidate new host and
    /// returns immediately -- the modal is already closed by the
    /// caller before this runs, matching every other slow mutation in
    /// this app (the outcome is reported later via `status_message`,
    /// not by keeping the form open across the async gap). Uses
    /// `zfs::run_checked` (not a bare `SshRunner::run`) specifically
    /// because `SshRunner::run` alone does not check the remote
    /// command's exit status -- an unreachable host or a rejected key
    /// still returns `Ok` from the raw call, just with a non-zero
    /// `CommandOutput::status`.
    pub fn begin_add_host(&mut self, name: String, target: String) {
        self.status_message = Some(format!("Connecting to '{target}'..."));
        let tx = self.tx.clone();
        let name_for_thread = name;
        let target_for_thread = target;
        std::thread::spawn(move || {
            let runner = crate::exec::ssh::SshRunner::new(target_for_thread.clone());
            let result = crate::zfs::run_checked(&runner, "true", &[], &format!("ssh {target_for_thread}")).map(|_| ());
            let _ = tx.send(WorkerMsg::HostProbe(name_for_thread, target_for_thread, result));
        });
    }
```

    /// Pushes `name`/`target` onto the live inventory (always, even if
    /// persisting below fails -- hot-reload's whole point is that the
    /// host is usable for the rest of this session regardless) and
    /// then persists it to `config_path` by loading the current
    /// config, appending, and saving. The inventory push happening
    /// first and unconditionally is what guarantees it's never rolled
    /// back by a later persistence failure.
    pub fn apply_new_host(&mut self, config_path: &Path, name: String, target: String) -> Result<()> {
        self.hosts.push(Host {
            name: name.clone(),
            runner: Arc::new(SshRunner::new(target.clone())),
        });
        let mut config = Config::load(config_path)?;
        config.hosts.push(HostConfig { name, ssh_target: Some(target) });
        config.save(config_path)
    }
